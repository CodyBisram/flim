# Review notes for 2026-11-06

## 1. Flim/V2/V2Friends.swift:198-216, a cancelled Find offer can leave the cover stuck open over the wrong tab

`offerFindOnce()` sets `showFind = true` (line 212), sleeps 1200ms (line 213), then checks
`if findAppeared || Task.isCancelled { return }` (line 214) before resetting `showFind = false`
(line 215). The task is keyed by `FindOfferKey(frontmost: isFrontmost, userId: ...)` (line 135),
so SwiftUI cancels and restarts it the instant `isFrontmost` changes. If that cancellation lands
while `showFind` is already true and the loop is mid-sleep, the function hits the cancelled branch
at line 214 and returns without ever executing the `showFind = false` cleanup on line 215.

Failure scenario: a cohort-code account lands on Friends, `offerFindOnce` presents the Find cover
(`showFind = true`), and within the following 1.2 seconds the person switches to another tab
(Friends stops being frontmost, flipping the task's id and cancelling it mid-sleep). `showFind`
is never reset, so the `fullScreenCover(isPresented: $showFind)` on `V2FriendsPlace` stays
presented. Since `V2FriendsPlace` remains mounted in the inactive tab, the Find screen stays on
top of whatever tab the person switched to, with no visible path back except finding Find's own
dismiss control, until something else happens to touch `showFind`.

Severity: medium.

## 2. Flim/V2/V2Rolls.swift:1166,1186, V2RollTime still cuts "today/tonight" at midnight, not the app's 4am day boundary

This commit adds an hour check (`>= 17`) to distinguish "tonight" from "today" and "TONIGHT" from
"TODAY" (lines 1166, 1186), but both branches still gate on `calendar.isDate(date, inSameDayAs:
now)`, a plain midnight-calendar-day comparison. `FeedUnit.dayKey` documents exactly this
mismatch for the rest of the app (`Flim/Models/FeedUnit.swift:26-28`): a 02:00 shot files under
the previous day because a midnight cut splits a single night in two. `V2NewRollView` lets a
roll's `revealAt` be moved to an arbitrary time (`V2Rolls.swift:1027-1030`), so a reveal between
00:00 and 04:00 is reachable.

Failure scenario: it's 11 PM and a roll is set (or moved) to open at 2 AM the same night. `now`
is 23:00, `date` is 02:00 the next calendar day, so `calendar.isDate(date, inSameDayAs: now)` is
false and the function falls through to the "tomorrow" branch (`calendar.isDate(date,
inSameDayAs: tomorrow)` is true for a calendar-day-after-now date), labeling the roll "tomorrow,
2:00 AM" / "TOMORROW 02:00" on the card, its lid, and `V2DevelopAskSheet`'s "It opens tomorrow,
2:00 AM" copy, even though by the app's own 4am convention this is still tonight's roll closing
tonight.

Severity: low.
