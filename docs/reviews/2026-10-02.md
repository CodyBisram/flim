## medium: web/admin.html's push-health "today" is the viewer's local calendar date, not the server's New York day

`web/admin.html:1486-1487` (new code, `renderPushHealth`):

```js
var now = new Date();
var newest = now.getFullYear() + "-" + pad2(now.getMonth() + 1) + "-" + pad2(now.getDate());
```

`admin_push_health()` (`supabase/migrations/2026-10-01_admin_dashboard_batch.sql:260-269`,
folded into `supabase/schema.sql:16124-16133`) buckets every row by the America/New_York day
(`(pd.updated_at AT TIME ZONE 'America/New_York')::date`). `dayBack()` right above this code
(`web/admin.html:1461-1465`) is careful to step by UTC date parts, with its own comment
explaining why ("Day keys are moved by their parts in UTC, never parsed as local midnight,
for the same reason weekLabel avoids Date: west of UTC that is the day before"). The `newest`
seed breaks that rule by reading the browser's local calendar date instead.

Failure scenario: an admin opens the dashboard from any timezone ahead of America/New_York
(all of Europe, Asia, Pacific, and UTC itself) at a moment when the local calendar date has
already rolled over but New York's has not. `newest` seeds to a day no `push_deliveries`,
`digest_state` or `one_shot_push` row exists for yet, so `dayBack(newest, i)` (line 1514)
walks the 7/14-day window back from that phantom day: the real latest NY day's numbers render
one column later than "today," and the leading column is a zero-filled day that has not
happened. The phantom empty day also feeds the quiet-streak detector (lines 1526-1529,
`while (streak < days.length && !(...sent > 0)) streak++`): a push kind quiet for only 2 real
NY days now measures `streak = 3`, crossing the `streak >= 3` threshold and firing a false
"0 sent for 3 days" outage pill a day early. The 14-day `kd.sent`/`kd.failed` totals are
unaffected (summed directly from server rows); only the per-day columns and the outage flag
are wrong.
