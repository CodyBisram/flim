# Review notes for 2026-10-24

## Flim/Services/NotificationActions.swift:146-151 (performReact), Flim/Services/RemotePush.swift:436-439

A failed reaction write now opens its post for whoever is signed in at that moment, not whoever pressed
the button, because the session re-check that guards the analogous follow-back path was dropped here.

**Failure scenario:** Signed in as account A, the owner receives a push naming a post and presses a
reaction button. `performReact` checks `session.user.id == A` and starts the `post_reactions` insert.
Before that insert resolves, the device switches to account B (sign out, sign back in as someone else,
or however an account change reaches `AccountScopeHook`/`.flimAccountDidChange`), which flushes
`PendingPushDestination` and resets all per-account caches. The insert then fails under B's session (the
write no longer matches the signed-in account) and lands in `performReact`'s generic `catch`, which logs
and returns `true` with no re-check of who is signed in now. `RemotePush.swift`'s handler sees `true` and
unconditionally calls `PendingPushDestination.store` and posts `.openPushDestination`, so `MainTabView`,
now showing B, immediately navigates to A's post, a jump B never asked for, triggered by a button B
never pressed. `performFollowBack`, three functions above in the same file, still re-checks
`current.user.id == action.recipient` before holding a destination on exactly this kind of failure
(fixed 2026-10-14, 29f94d7, docs/reviews/OPEN.md row for that date); `performReact`'s own catch had the
same re-check before this diff removed it in favor of the new `-> Bool` return.

Severity: low
