# Review notes for 2026-11-05

## 1. Flim/V2/V2Darkroom.swift:355,366-367, Kept count includes shots the Kept list and strip hide

`keptCount` (line 367) is read from `photos.personalPhotoCount` (line 355), which counts every row
with `is_sorted = true` and no `develops_at` filter. The `kept` array shown on the Darkroom place
and passed to the Kept screen (line 366, and `V2Kept.swift:194`) is now filtered to `\.isReady`
(`develops_at <= now`) so a roll's shots stay out of Kept until the roll opens. The count was not
given the same filter.

Failure scenario: a user joins a roll that has not revealed yet and takes a shot in it. Rolls
insert `is_sorted: true` immediately (shots skip the sort deck), so `personalPhotoCount` counts
that shot right away and the Darkroom shows "Kept · 1" (or higher). The actual Kept list behind
that button, and the "last few you kept" strip, exclude the shot until the roll reveals, so tapping
"Kept · 1" opens an empty (or undercounted) list. The same stale count also feeds the `(keptCount ??
0) == 0` check at line 158 that chooses between the "day one" and "all sorted" empty states, so a
brand-new account whose only sorted photo is an unrevealed roll shot sees the "all sorted" empty
state instead of "day one."

Severity: medium.

## 2. Flim/V2/V2RollPrints.swift:759, V2RollMore reads the stale `is_developed` cache instead of the time-based `isReady`

`V2RollMore.load()` filters the roll's photos with `p.filter(\.isDeveloped)`. `Photo.isDeveloped`
is a stored column maintained by a cron job on an "untracked cadence" (per
`PhotoService.swift:2554-2556`'s own comment, which names `Photo.isReady` as the truthful,
time-based signal every other "is this ready" check in the app uses). `DarkroomViewModel.swift:143-144`,
which splits the same kind of roll/personal photo list for the screen `V2RollMore` replaces, already
uses `\.isReady` and even patches the stale `isDeveloped` field locally once `isReady` flips true, to
compensate for exactly this lag.

Failure scenario: a member opens a roll immediately after its reveal (`develops_at`/`reveal_at` has
passed, so the reveal slideshow plays and `isReady` is true for every photo) and taps More before
the cron job has flipped `is_developed` on those rows. `V2RollMore` shows "nothing yet" for every
member and hides the "Save all to Camera Roll" row entirely (`savable.isEmpty`), even though the
roll's prints are visibly developed everywhere else in the app. It only self-corrects once the cron
runs and the screen is reopened.

Severity: medium.
