## 1. scripts/asc_watch.py:141-143 (medium)

The deadline branch notifies the owner that the watch stopped but discards whether the push
landed, and still returns 0.

Failure scenario: the watch hits `WATCH_DEADLINE` while the ASC build is still pending, and the
`notify()` call to notify-owner fails (network blip, the function briefly down). `main()` still
returns 0. The GitHub Actions run therefore has `conclusion: success`. The backstop
(`scripts/asc_watch_backstop.py:decide`) treats any non-failed newest run as "the watch is over"
and disables itself (`action == "off"`). The owner is never told the watch ended and nothing
resumes checking App Store Connect; the review state goes unmonitored until the owner happens to
check by hand. This is the same "a push cannot be unsent, so check it landed" discipline the
DONE-state branch two lines above already applies (it checks `told` and returns 1 if the push
failed) and the stop-run branch at the top of `main()` also applies (`return 0 if ok else 1`);
the deadline branch is the one path in this file's own tonight's rewrite that does not.
