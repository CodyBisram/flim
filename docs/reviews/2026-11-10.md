# Review notes for 2026-11-10

Range: 3c3e69a..a3155f1 (main), the 1.7 "desk" redesign (Paper/Slate theme, new tab bar, Darkroom
Post screen, Friends tabs). All findings below sit behind `AppInfo.is17` / `FLIM_17`, which is on
only in the Beta configurations, so none of them reach the App Store build yet.

1. **Flim/Views/Main/MainTabView.swift:961-965 vs :467-468** (medium). An existing account whose
   notification primer was already shown once and dismissed undecided gets permanently skipped on
   its first 1.7 launch. Failure scenario: a 1.6 account with `timesShown == 1`, `decided == false`
   opens 1.7; `DeskUpdateCard`'s `fullScreenCover` is up at launch, and one second later
   `maybeShowNotifPrimer()` fires and spends its budget (`didRetryUnaskedNotifPrimer = true`,
   `notifPrimerPresentationCount += 1`) before presenting `showNotifPrimer`, with no guard on
   `deskUpdateCardSeen`. If the update card's cover suppresses or drops the primer's sheet, that
   account has now used its one retry and is never asked about notifications again on any later
   run.

2. **Flim/Views/Darkroom/DeskPostView.swift:31, used at :43** (medium). "Send to Spotlight too"
   never appears for an account that opens Post without having first opened Feed or the sort deck.
   `spotlightOffered` reads `feed.currentSpotlightEntry`, which requires
   `ownSpotlightEntryIsCurrent` (`FeedService.swift:1006`), set only by `refreshOwnSpotlightEntry()`
   from `FeedView.swift:1174`, `SortDeckView.swift:622,824`, or `loadSpotlightMenuInputs`
   (`FeedService+Spotlight.swift:315-316`, which itself returns early for an empty post list).
   Failure scenario: cold launch straight into the Darkroom tab, select a developed shot, tap Post
, the Spotlight toggle is silently absent even though the week is open and the slot is free,
   every time, for any account that has never posted.

3. **Flim/Views/Darkroom/DeskPostView.swift:212-228** (medium). A post whose caption saves but
   whose tags fail to save is reported as a full success with no notice. `createPost` returns
   `tagsSaved: false` on that failure branch (`FeedService.swift:1997`), but `post()` discards
   `created.tagsSaved` entirely. Failure scenario: tag a friend, tap Post; the `posts` insert
   succeeds and the `post_tags` insert fails on a flaky connection, `Haptics.success()` fires, the
   shot goes up untagged, the tagged friend gets no push, and the user is never told, unlike the 1.6
   composer's explicit warning for the same case.

4. **Flim/Views/Feed/UserPageView.swift:438-440, rendered at :473** (medium). "Unknown friend
   count" renders as "0 friends" instead of omitting the segment. `deskFriendCount` intersects
   `feed.followingIds`/`followerIds`, both empty until `load()` fills them later
   (`UserPageView.swift:1142-1143`), and `loadFollowers` keeps the last-known (empty, if never
   loaded) set on a failed read (`FeedService.swift:163`). Failure scenario: launch straight into
   the You tab without visiting Feed first, the header reads "@handle · 0 friends" until both
   round trips land, then jumps to the real count; offline, it reads "0 friends" for the whole
   session for someone with real friends.

5. **Flim/Views/Feed/FeedView.swift:479 vs Flim/Views/Main/MainTabView.swift:789,796** (medium).
   Activity is pushed with `.navigationDestination(isPresented:)` inside the `NavigationStack`
   whose visible content is otherwise driven by `feedPath`, but an `isPresented`-based destination
   is not part of the bound `NavigationPath` and is not popped by resetting it. Both route handlers
   that want "the Feed, at its root" (`.feed` and `.spotlightWeek`) reset only `feedPath =
   NavigationPath()` and never touch `showActivity`. Failure scenario: a user is reading Activity
   when a daily-digest push arrives and routes `.feed`; `feedPath` is cleared but `showActivity`
   stays true, so the view the notification named is never shown and the user remains on the
   already-pushed Activity screen.

6. **Flim/Views/Main/MainTabView.swift:343 vs Flim/Views/Main/DeskTabBar.swift:145,156** (low).
   The You tab's red dot is hardcoded off (`youDot: false`) even though `DeskTabBar` wires it to a
   real signal. 1.6 flags an earned-seal badge via `feed.unseenBadgeCount`
   (`UserPageView.swift:498-500`), but 1.7 drops that avatar badge with nothing replacing it in the
   tab bar. Failure scenario: earn a seal in 1.7, no dot anywhere signals it until the user happens
   to open the You tab and see the "Seals ·" badge already on the page it would have sent them to.

7. **Flim/Views/Feed/UserPageView.swift:438-440 vs Flim/Views/Feed/DeskFriendsView.swift:21**
   (low). The header's friend count does not subtract blocked accounts, while the Friends list it
   opens does (`FeedService.swift:426,438`). Failure scenario: you and a mutual follow block each
   other; your page still counts them as a friend in the header while the Friends sheet omits them,
   so the header number and the list it opens disagree.

8. **Flim/Views/Feed/DeskFriendsView.swift:74,113** (low). The Requests tab's count label
   (`"Requests \(incoming.count)"`) counts incoming requests only, while the tab body renders both
   `incoming` and `outgoing`, and the empty state at line 113 checks both. Failure scenario: send 3
   friend requests and receive none, the tab reads "Requests 0" directly above three rows under
   "YOU ASKED".

9. **Flim/Views/Camera/CameraView.swift:1386,1405** (low). `chipTapped` is cleared only inside
   `onChange(of: camera.zoomFactor)`, so a chip tap that produces no zoom change leaves the latch
   set and silently eats the next real zoom change. Failure scenario: already at 1x, tap the 1x
   chip, nothing changes so the `onChange` never fires to clear the latch; the next pinch or drag
   that would normally open the zoom dial is consumed clearing the stale latch instead.

10. **Flim/Views/Camera/CameraView.swift:352,463** (low). 1.7's camera has no "N to sort" control;
    `unsortedCount` is still tracked but never rendered on this path, and the last-shot tile can
    show an unsorted photo (`fetchLatestPersonalShot` does not filter `is_sorted`,
    `PhotoService.swift:2503`). Failure scenario: shoot five frames in 1.7, they sit unsorted with
    no on-camera indication, and tapping the last-shot tile opens a Darkroom view that does not
    contain that shot, with the only route to the sort deck being the Darkroom tab's own banner.
