## 1. medium, Flim/Views/Feed/DeskFriendsView.swift:282 (`load()`), Flim/Services/FeedService.swift:493-515 (`fetchFollowers`/`fetchFollowingProfiles`)

`fetchFollowers`/`fetchFollowingProfiles` read a failed request as empty (`(try? ...) ?? []`), so
`load()`'s guard at :282 (`if !(fetchedFollowers.isEmpty && fetchedFollowing.isEmpty) ||
(followers.isEmpty && following.isEmpty) { ... }`) cannot tell a genuine zero from a failed fetch
once the in-memory lists are already non-empty: both terms are false, so the stale lists are kept
and then re-persisted via `feed.cacheFriendsLists` at :287.

Failure scenario: account A has exactly one follower B, and opens Friends once, caching
`followers = [B]` to `SocialGraphCache` and showing B under Requests. B later cancels the follow.
A relaunches and opens Friends: the disk cache seeds `followers = [B]` at :269-273 before the
network reads land; `fetchFollowers` correctly returns `[]` this time, but since `followers` is
already non-empty the guard at :282 evaluates false and keeps `[B]`. Line 287 re-persists `[B]` to
disk. The Requests tab permanently reads "Requests 1" with B's row and an Add action for a follow
that no longer exists, surviving every future launch and pull-to-refresh, and tapping Add follows
someone who never asked.

## 2. low, Flim/Services/FeedService.swift:427,434,449,478 (`follow`/`unfollow`/`noteFollowMadeElsewhere`), :159-164 (`persistGraph`)

`follow`, `unfollow`, and `noteFollowMadeElsewhere` all mutate `confirmedFollowingIds` but never
call `persistGraph()`, unlike the read path at :194 and :238, so a local follow-graph change the
user just made is never written to `SocialGraphCache`.

Failure scenario: account A's last full read landed with B not followed, persisting that to disk.
A follows B; `confirmedFollowingIds` gains B in memory but the on-disk snapshot still lacks B. A
relaunches on a slow or offline connection: `restoreSocialGraph` (:133-138) loads the stale
snapshot and sets `confirmedFollowingIds` without B, so B's profile page shows the unfollowed
state (`UserPageView.swift:291`), the follow button offers to follow again, and `deskFriendCount`
undercounts B as a friend until the next successful read overwrites it.
