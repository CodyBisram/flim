1. Flim/Views/Rolls/RollDetailView.swift:719 (paired with RollRevealView.swift:544-548)
Defect: the reveal's "Start another with this group" button dismisses the fullScreenCover and sets a sibling sheet flag on the same presenting view in one synchronous handler, so the follow-up sheet can fail to appear.
Failure scenario: user finishes a roll reveal and taps "Start another with this group." `onStartAnother` calls `dismiss()` (which flips `showReveal` to false on RollDetailView) and then immediately sets `showFollowUp = true` in the same closure. Both a `.fullScreenCover(isPresented: $showReveal)` and a `.sheet(isPresented: $showFollowUp)` live on the same RollDetailView instance, so the new sheet's presentation request races the cover's own dismissal transaction and can be silently dropped, leaving the user back on RollDetailView with no CreateRollView sheet and no visible response to the tap. Every other cross-view "dismiss, then trigger the next screen" transition in this codebase (JoinRollView, CreateRollView, SortDeckView's posted-notice "View" button, ActivityFeedView's push destination) goes through NotificationCenter instead of flipping a second local state var on the dismissing view, which avoids exactly this race.
Severity: medium

2. Flim/Views/Darkroom/SortDeckView.swift:449
Defect: the "Posted to your page" confirmation banner can be dismissed early by a stale timer left over from an earlier publish.
Failure scenario: sort two photos in quick succession, publishing both (right-swipe or Post) within a few seconds of each other, which is the normal way this screen is used during a batch triage session. Committing the first publish sets `postedNotice = true` and schedules an unconditional `Task { sleep 3s; postedNotice = false }`. If the second publish also commits and shows its own "Posted to your page" banner before the first timer has fired, the first timer still fires on schedule and sets `postedNotice = false`, hiding the confirmation for the second (still-fresh) post well before its own 3 seconds are up. The banner has no way to tell which post it is confirming, so an older completion can cut off a newer one's confirmation.
Severity: low
