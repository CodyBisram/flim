# Review notes for Aug 30

## Flim/Views/Feed/FeedView.swift:218

`inviteQuota` is fetched once in the view's `.task {}` block and is never refreshed by `reload()` (line 657) or any other event while the Feed tab stays mounted, even though this commit window's own fix was meant to stop this screen from handing out a dead invite code.

Failure scenario: a user with `invite_uses_remaining = 1` lands on the empty Feed, `inviteQuota` resolves to `.remaining(1)`, and the "Invite someone" ShareLink (guarded at line 609 by `inviteQuota != .remaining(0)`) is shown. They share the code to a first friend. While they stay on the Feed tab, that friend's redemption completes server-side and their remaining count drops to 0, but the ShareLink stays visible with the same stale code (pull-to-refresh via `reload()` does not touch `inviteQuota`, and `.task` only re-fires on tab-switch, not on backgrounding or a manual refresh). They share the same code to a second friend, who then hits a redemption failure this fix was supposed to prevent.

Severity: low-medium. No data corruption or cross-account exposure; the redemption fails cleanly with the new `InviteCopy.redeemFailed` copy, but the sharer isn't warned before sending out a code that is already dead.
